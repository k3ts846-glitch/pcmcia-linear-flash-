# PCMCIA FLASH TOOL — инструкция по использованию

Карта: 16/32 МБ PCMCIA linear flash · Ноутбук: Fujitsu-Siemens AMILO Pro V2030D
Система: Debian 12 i386 · Версия программы: 2.4

Инструкция идёт по порядку: от записи архива на флешку до восстановления,
если что-то пошло не так. Всё, что здесь написано, проверено на наборе:
команды, пути, поведение на флешке с FAT32 (пробелы и кириллица в именах
файлов допускаются).

---

# Часть 1. Записать набор на USB-флешку

## 1.1. Что понадобится

- USB-флешка от 128 МБ (набор занимает ~21 МБ, но лучше с запасом под образы карт);
- компьютер с Linux (ваш ноутбук подойдёт, если он уже работает);
- файл `pcmcia-flash-kit.tar.gz` (21 МБ).

Флешку форматировать не нужно, если на ней есть место. Файловая система —
любая (FAT32, ext4). Если на флешке есть важные данные — сохраните их: дальше
мы только копируем файлы, но лучше не рисковать.

## 1.2. Вставить флешку и узнать её точку монтирования

```bash
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT,LABEL
```

Пример вывода:

```
NAME   SIZE FSTYPE MOUNTPOINT LABEL
sda  238.5G ext4   /
sdb   14.6G vfat   /media/user/KINGSTON
```

Здесь флешка — `sdb`, смонтирована в `/media/user/KINGSTON`.
**Не перепутайте с `sda` (это ваш диск).** Если флешка не смонтировалась
автоматически — смонтируйте вручную:

```bash
sudo mkdir -p /mnt/usb
sudo mount /dev/sdb1 /mnt/usb        # вместо sdb1 — ваше устройство из lsblk
```

## 1.3. Скопировать архив и распаковать

```bash
# 1) копируем архив на флешку (подставьте свой путь)
cp pcmcia-flash-kit.tar.gz /media/user/KINGSTON/

# 2) распаковываем прямо на флешке, чтобы там лежал готовый набор
cd /media/user/KINGSTON
tar -xzf pcmcia-flash-kit.tar.gz

# 3) проверяем, что распаковалось
ls pcmcia-flash-kit
```

Должно быть видно:

```
README_FIRST.txt  pcmcia_gui.py  gui.sh  pcmcia_flash.sh
debs/  linux/  tests/  demo/  windows/  ...
```

## 1.4. Правильно отмонтировать (не выдёргивать!)

```bash
sync
sudo umount /media/user/KINGSTON     # или /mnt/usb, если монтировали вручную
```

Выдёргивание без `umount` — самая частая причина «архив на флешке битый».
Проверить целостность потом можно так:

```bash
md5sum pcmcia-flash-kit.tar.gz
```
Сверьте с тем, что указано в конце этого файла (раздел 12).

## 1.5. Что должно оказаться на флешке

```
/media/user/KINGSTON/
├── pcmcia-flash-kit.tar.gz          ← архив (резервная копия, можно держать)
└── pcmcia-flash-kit/                ← распакованный набор
    ├── README_FIRST.txt             ← краткая памятка
    ├── ИНСТРУКЦИЯ.md                ← этот файл
    ├── pcmcia_gui.py                ← графическая программа
    ├── pcmcia_direct.py             ← прямое чтение через /dev/mem (обход)
    ├── report.sh                    ← один запуск → один отчёт для переписки
    ├── collect_all.sh               ← полный отчёт (выполняется на ноутбуке)
    ├── remote_collect.sh            ← запуск collect_all.sh по SSH с другого ПК
    ├── remote_collect.ps1           ← то же самое для Windows (PowerShell)
    ├── gui.sh                       ← запуск GUI (сам спросит пароль)
    ├── pcmcia_flash.sh              ← консольное меню
    ├── linux/                       ← скрипты по одной операции
    ├── debs/                        ← 72 пакета .deb (для работы без интернета)
    ├── tests/                       ← ~870 проверок (карта не нужна)
    └── demo/                        ← скриншоты
```

Минимально достаточно **двух файлов**: `pcmcia_flash.sh` + архив рядом.
Скрипт сам найдёт архив, распакует во временную папку и возьмёт пакеты
оттуда. Удобно, если флешка маленькая.

# Часть 1.6. Что почитать про сами карты

В наборе лежит справочник `PCMCIA_LINEAR_FLASH_СПРАВОЧНИК.md`. Он нужен не
для общего образования, а чтобы понимать, что набор делает и чего он
делать не станет:

* чем линейная флеш отличается от SRAM (у SRAM данные держатся на
  батарее) и от ATA-карты (её видно как диск, линейную — нет);
* где лежит паспорт карты и почему стирание первого блока может его
  уничтожить;
* что означает переключатель защиты от записи и почему набор
  останавливается, если в паспорте отмечен этот переключатель;
* какие бывают микросхемы (сектор 16/64/128 КиБ, запись байтом или
  страницей 32 байта, 5 В или 12 В на Vpp) и чем это грозит.

Читать целиком не обязательно; раздел 8 «Типовые отказы» полезен, когда
что-то пошло не так.

## 1.6.1. Проверить набор, не трогая карту

Перед работой с картой имеет смысл убедиться, что набор доехал до ноутбука
целым: двойной щелчок по `ПУСК.cmd` и пункт 12 меню либо

```
python pcmcia-kit.pyw --text selftest            # на Windows-машине
bash ~/pcmcia-flash-kit/pcmcia_ctl.sh selftest   # прямо на ноутбуке
python tests/test_win.py                         # проверки самого пульта
```

Тесты работают на модели микросхем, карта и root не нужны. Быстрый режим
(по умолчанию) занимает около 20 секунд, полный (`selftest --full`) —
около минуты и прогоняет всё, включая запись 8 МиБ на модели.

# Часть 2. Первый запуск на ноутбуке

## 2.1. Вставить флешку и карту

1. **Карту вставьте до включения ноутбука** — слот TI PCIxx21 не всегда
   подхватывает 16-битные карты «на горячую». Если карта уже была вставлена
   при загрузке, это лучший вариант.
2. Вставьте флешку.
3. Загрузитесь в Debian 12.

## 2.2. Открыть набор

Флешка обычно монтируется в `/media/<пользователь>/<метка>`. Найти её:

```bash
lsblk -o NAME,SIZE,MOUNTPOINT,LABEL
cd /media/*/*/pcmcia-flash-kit         # если метка без пробелов
```

Если в имени флешки пробелы или кириллица — проще через файловый менеджер:
откройте флешку, войдите в папку `pcmcia-flash-kit`, щёлкните правой кнопкой
по пустому месту → «Открыть в терминале».

## 2.3. Важно: `bash ./скрипт`, а не `./скрипт`

Флешка с FAT32 монтируется с запретом исполнения файлов. Поэтому:

```bash
# ТАК НЕ РАБОТАЕТ — «Permission denied»
./pcmcia_flash.sh

# ТАК РАБОТАЕТ
bash ./pcmcia_flash.sh
```

Это не ошибка набора, это свойство FAT32. Для программы на Python всё проще:
`python3` всегда запускается.

Внутри скриптов такие вызовы уже учтены: `flashcard.sh write` вызывает сам
себя как `bash "$0" verify`, а не `"$0" verify` — иначе на флешке сверка
после записи обрывалась бы на «Permission denied». То же для `fill`,
который внутри вызывает `write`.

## 2.4. Проверка перед работой (30 секунд, root не нужен)

```bash
bash ./pcmcia_flash.sh --selftest
```

Что должно быть в выводе:

```
Каталог скрипта : /media/user/KINGSTON/pcmcia-flash-kit
Архитектура     : i386                       ← важно: i386, не amd64
Пакеты          : .../debs
Количество .deb : 72
Модуль pcmciamtd: найден
Утилиты: + mtd_debug + flash_erase + flashcp ...
```

Если `Архитектура: amd64` — установлена 64-битная система, драйвер
`pcmciamtd` в ней не собран, карта не заработает. Нужна переустановка i386.

Если `Модуль pcmciamtd: НЕ НАЙДЕН` — установлено не то ядро
(должно быть `686` или `686-pae`, не `amd64` и не `rt`).

Суть проверки — `--selftest` или `--doctor`:

```bash
python3 pcmcia_gui.py --doctor     # то же, но подробнее и с состоянием карты
```

# Часть 3. Установка (один раз)

## 3.1. Утилиты: через интернет или офлайн

**Если интернет на ноутбуке есть:**

```bash
sudo apt update
sudo apt install -y mtd-utils pcmciautils pciutils kmod python3-tk
```

**Если интернета нет (обычный случай для этого ноутбука):**

```bash
cd /media/*/*/pcmcia-flash-kit
sudo dpkg -i debs/*.deb
sudo apt-get -f install -y
```

`apt-get -f install -y` нужен: `dpkg` ставит пакеты по одному и может
споткнуться о порядок зависимостей — `apt` дособерёт.

Проверка:

```bash
mtd_debug --version
pccardctl --version
python3 -c "import tkinter; print('tkinter ок')"
```

**То же самое делает пункт 1 меню** — после установки он сам показывает, что
именно стоит. Если утилиты уже были, вывод короткий:

```
OK  уже установлены — проверяю, что работают
Проверка версий (для отчёта):
    mtd-utils 1:2.1.5-1 установлен
    pcmciautils 018-13 установлен
    pciutils 1:3.8.0-1 установлен
    kmod 30+20221116-1 установлен
Лог установки: /tmp/pcmcia_flash.log
Что дальше: пункт 2 (настроить слот), затем пункт 3 (состояние карты).
```

Что означают строки:

| Строка | Что значит | Если её нет |
|---|---|---|
| `OK уже установлены` | все четыре пакета на месте | ставился офлайн из `debs/` — смотрите лог |
| `Проверка версий` | `dpkg-query` подтвердил пакет в системе | пакет числится, но не установлен — повторите пункт 1 |
| `! mtd_debug не отвечает` | файл есть, но не запускается | битый пакет: `sudo dpkg -i --force-confmiss debs/mtd-utils*.deb` |
| `Лог установки` | где искать подробности | — |

**Важно:** пункт 1 проверяет только первый уровень. Их три:

```
1) УТИЛИТЫ СТОЯТ      пункт 1 меню, mtd_debug --version, dpkg -l mtd-utils
2) СЛОТ НАСТРОЕН      пункт 2 меню, lspci | grep CardBus, lsmod | grep pcmciamtd
3) КАРТА ВИДНА        пункт 3 меню, python3 pcmcia_gui.py --doctor, /dev/mtd0
```

Если пункт 1 сказал «OK», а карта не видна — проблема не в утилитах,
а во втором или третьем уровне: смотрите часть 9, раздел «Карта не появилась».

## 3.2. Настроить слот и драйвер (один раз, нужен root)

**Вариант А — через графику** (рекомендую):

```bash
cd /media/*/*/pcmcia-flash-kit
bash ./gui.sh
```

`gui.sh` сам попросит пароль sudo. В окне: вкладка **«Настройка»** →
кнопка **«Настроить слот и загрузить драйверы»**, Vpp = **5.0 В** (значение
по умолчанию).

**Вариант Б — без графики:**

```bash
sudo bash ./linux/setup_linear_flash.sh
```

**Что происходит:** скрипт находит CardBus-мост через `lspci`, берёт его окна
памяти и записывает в `/etc/pcmcia/config.opts`; создаёт
`/etc/modprobe.d/pcmciamtd.conf` с `vpp=50 setvpp=1`; загружает модули
(`yenta_socket`, `pcmcia`, `mtd`, `jedec_probe`, `cfi_probe`, `pcmciamtd`).

**Vpp — важное:** 5.0 В — правильный выбор почти всегда. 3.3 В — только если
на карте явно написано 3.3 V. **12 В ставить нельзя:** на этом ноутбуке их нет,
а неверное напряжение может повредить карту. Программа не даст ввести ничего,
кроме 50 и 33.

## 3.3. Проверить, что карта видна

```bash
python3 pcmcia_gui.py --doctor
```

Хороший результат:

```
Устройство    : /dev/mtd0 — найдено (MTD)
  размер      : 16777216 (16.00 МиБ), блок 131072, регионов 1
  запись      : разрешена
  модель      : Intel Series 2+ / Value
```

Если «не найдено» — часть 9, раздел «Карта не появилась».

# Часть 4. Графическая программа: по шагам

Запуск:

```bash
cd /media/*/*/pcmcia-flash-kit
bash ./gui.sh
```
(или `sudo python3 pcmcia_gui.py`, если хотите ввести пароль вручную)

## 4.1. Вкладка «Карта»

Это главный экран. Сверху — состояние карты, ниже — кнопки операций.

**Порядок первого знакомства:**

1. **«Идентификатор (CIS)»** — паспорт карты. Смотрите строку `PRODID_2`:
   - `SERIES2-02` → Intel Series 2 (28F008SA): по документации 5 В, но часть
     карт разводит Vpp на 12 В → **неизвестно**, проверяется пробой сектора;
   - `SERIES2-20`, `S2E8` → Series 2+ / Value → пишется;
   - `VALUE 100`, `AMD`, `Sharp` → пишется.
2. **«Проверить слот»** — покажет окна памяти и состояние слота.
3. **«Прочитать карту в файл…»** — снять образ (обязательно, если на карте
   есть нужные данные).
4. **«Тест записи (0xFF)»** — только если данные на карте не нужны.

**Про галочки:**

- ☑ **«Стирать всю карту перед записью»** — оставьте включённой. Если выключить,
  остаток карты (если образ меньше карты) сохранит старые данные: `flashcp`
  стирает только область под образ.
- ☑ **«Проверять после записи»** — оставьте включённой: после записи карта
  читается обратно и сравнивается с файлом.

**Про кнопку «Отмена»** — она работает в любой длинной операции (стирание,
запись, чтение, сверка). После отмены записи программа предупредит, что карта
может остаться в промежуточном состоянии — это правда, повторяйте запись
целиком.

## 4.2. Что значат предупреждения сверху

| Надпись | Что делать |
|---|---|
| «Карта не найдена» | часть 9: карта не появилась |
| «РЕЖИМ ТРЕНИРОВКИ: … обычный файл» | вы указали файл вместо карты (`MTD=/tmp/x.bin`); так можно учиться, реальная карта не затрагивается |
| «Карта ЗАЩИЩЕНА от записи» | переключатель WP на торце карты, снимите |
| «Карта, вероятно, 12-вольтовая» | запись не пойдёт, это железо, а не программа |
| «У карты несколько регионов стирания» | нормально: стирание идёт целиком |
| «Размер … не похож на 16 или 32 МБ» | CIS не читается, нужен `force_size` (часть 9) |

## 4.3. Вкладка «Просмотр / правка»

Смотреть и менять отдельные байты.

- **Смещение** — в шестнадцатеричном виде: `00010000` = 64 КиБ.
- **Длина** — из списка (64…1024 байта).
- Кнопки **‹ ›** листают по одному блоку вперёд-назад.
- Внизу — «Записать байты по смещению»: вводите hex (`DE AD BE EF`) и жмёте
  «Записать».

⚠ Правка байтов внутри блока на стёртой flash-карте не работает: сначала
нужно стереть блок. Для обычной работы правка не нужна — используйте запись
образа.

## 4.4. Вкладка «Блоки»

Карта блоков: **зелёный** — стёрт (0xFF), **красный** — есть данные,
**оранжевый** — ошибка чтения блока.

- Кнопка **«Просканировать карту»** — читает всю карту (16 МБ займёт
  несколько секунд).
- **Клик по блоку** — показывает адрес и состояние.
- После записи/стирания карта обновляется автоматически.

Зачем: оранжевые блоки — это сбойные участки; если их много, карта ненадёжна.

## 4.5. Вкладка «Настройка»

1. **Утилиты** — «Установить утилиты»: сначала через `apt`, если не вышло —
   из `debs/` или из архива рядом (офлайн). Когда всё уже стоит, программа
   всё равно проверяет, что утилиты запускаются, и печатает их версии —
   это и есть ответ на вопрос «точно установилось?».
2. **Слот и Vpp** — Vpp 5.0 / 3.3 В, кнопка «Настроить слот и загрузить
   драйверы». Здесь же видно, какие окна памяти записаны в `config.opts`.
3. **Монтирование** — точка монтирования (по умолчанию `/mnt/card`).

## 4.6. Вкладка «Журнал»

Все операции с метками времени. Кнопки «Сохранить…» и «Очистить».
Копия пишется в `/var/log/pcmcia-flash-tool/pcmcia-flash-tool.log`
(ротация при 1 МБ).

При ошибке программа сохраняет отчёт с контекстом (mtd info, pccardctl,
dmesg, lsmod) в `/tmp/pcmcia-error-*.txt` — это то, что стоит прислать,
если что-то не работает.

## 4.7. Горячие клавиши

| Клавиша | Действие |
|---|---|
| **F1** | справка по клавишам |
| **F5** | обновить состояние карты |
| **Ctrl+R** | прочитать карту в файл |
| **Ctrl+W** | записать образ на карту |
| **Ctrl+V** | сверить файл с картой |
| **Ctrl+M** | просканировать блоки |
| **Ctrl+S** | сохранить отчёт |
| **Ctrl+L** | перейти к журналу |
| **Esc** | отмена текущей операции |

# Часть 5. Работа с образами

## 5.1. Снять образ (делать первым делом)

GUI: **«Прочитать карту в файл…»** → выберите, куда сохранить (лучше сразу
на флешку: `/media/user/KINGSTON/card16.bin`).

Консоль:

```bash
sudo bash ./linux/flashcard.sh backup /media/user/KINGSTON/card16.bin
```

Или интерактивное меню:

```bash
sudo bash ./pcmcia_flash.sh     # пункт 4
```

**Что происходит:** карта читается **дважды**, оба чтения сравниваются.
Результат:

- `OK: два чтения совпали, образ стабилен` — можно работать дальше;
- `ВНИМАНИЕ: чтения различаются` — карта или контакты нестабильны.
  **Не пишите на такую карту**, пока не разберётесь. Файл `.check` оставлен
  для сравнения, программа подскажет первое расхождение с адресом.

Рядом с образом создаётся `.md5` — контрольная сумма, чтобы потом убедиться,
что файл не испортился.

**Храните образ в двух местах.** Это единственная страховка.

## 5.2. Записать образ

GUI: **«Записать образ на карту…»** → выберите файл.

Перед записью программа:

1. откажется писать файл, целиком состоящий из `0x00` (это почти всегда
   ошибка выбора файла);
2. предупредит, если образ уже совпадает с содержимым карты (запись ничего
   не изменит, но сотрёт и запишет заново);
3. покажет в подтверждении тип содержимого и первые байты:

```
Содержимое: похоже на FAT/с файловой системой
Размер: 16.00 МиБ
MD5: 5f2c1a...
Первые байты: EB 3C 90 4D 53 44 4F 53 35 2E 30 00 00 00 00 00
```

Консоль:

```bash
sudo bash ./linux/flashcard.sh write /media/user/KINGSTON/new16.bin
```

Стирание всей карты выполняется **до** записи. Если нужно сохранить остаток:

```bash
sudo MTD_KEEP_TAIL=1 bash ./linux/flashcard.sh write new16.bin
```

GUI: **«Сверить файл с картой…»**. Консоль:

# Часть 6. Если нужны файлы, а не образ (FAT)

# Часть 6.5. Работа с Windows-машины (Python-пульт)

Если карта стоит в ноутбуке с Linux, а вы сидите за Windows, работать можно
оттуда: набор сам заходит на ноутбук по ssh и приносит результат обратно.
Нужен только Python 3.9+ (python.org). PowerShell и командные файлы больше
не используются.

```
python pcmcia-kit.pyw                            окно пульта (двойной щелчок)
python pcmcia-kit.pyw --text                     текстовое меню
python pcmcia-kit.pyw --text info                паспорт карты
python pcmcia-kit.pyw --text read                снять образ
python pcmcia-kit.pyw --text write -i card.bin   записать образ
python pcmcia-kit.pyw --text key                 вход по ключу (один раз)
```

После `py -3 -m pip install .` те же действия короче: `pcmcia-kit info`.
Без установки `python -m pcmcia_kit` пакет не найдёт: он ищет его там, куда
Python ставит библиотеки.

Что происходит при запуске (пять шагов, видно в выводе): папка на ноутбуке,
синхронизация набора (только изменившиеся файлы), отправка образа (если нужен)
со сверкой md5, работа с картой с показом хода, забор результата.

Пульт не устанавливает ничего на ноутбук: файлы кладутся в `/tmp/pcmcia-ctl`
и убираются в конце; снятый образ в `/root` остаётся, его могли не забрать.
При отказе входа, недоступном ноутбуке или неверном md5 работа
останавливается до записи на карту.

# Часть 8.1. Прямое чтение через /dev/mem (обход, когда драйвер не дал окно)

Если в dmesg есть `no high memory space available` и `/dev/mtd0` не появляется,
карту всё равно можно **прочитать** — в обход подсистемы PCMCIA. Окна CardBus
моста ядро уже назначило (`pci 0000:00:0c.0: CardBus bridge window 1
[mem 0x64000000-0x67ffffff pref]: assigned`), это физические адреса. Через
`/dev/mem` их можно отобразить и прочитать карту напрямую, как это делают
DOS-утилиты.

```bash
cd /media/*/*/pcmcia-flash-kit
sudo python3 pcmcia_direct.py --probe            # есть ли доступ к окнам
sudo python3 pcmcia_direct.py --cis              # ГЛАВНОЕ: паспорт карты (CIS)
sudo bash ./report.sh                            # то же + ядро/слот в один файл
sudo python3 pcmcia_direct.py                    # окна + что в начале карты
sudo python3 pcmcia_direct.py --read card.bin --double --size 16m
```

Или из меню: пункт **11**.

Что делает:

| Шаг | Что показывает |
|---|---|
| `--probe` | можно ли открыть `/dev/mem` и прочитать окно; если нет — почему |
| `--cis` | читает attribute memory карты (CIS): паспорт — производитель, модель, размер, тип. **Единственный способ отличить стёртую карту от неотвечающей** |
| без ключей | окна, первые 4 КиБ каждого, строки (обычно PRODID), маркеры `CIS` |
| `--read файл` | образ карты целиком; `--double` — два чтения и сверка |
| `--size auto` | размер по повторению адресных линий (окно 64 МиБ, карта 16/32) |
| `--addr 0x64000000 --len 4096 --hex` | точечное чтение с дампом |

Ограничения, о которых надо знать заранее:

1. **Только чтение.** Запись без драйвера не делается намеренно: некому
   выставить Vpp (напряжение программирования) и соблюсти тайминги команд
   микросхемы. «Записать наугад» — верный способ испортить карту.
2. **`0xFF` в обычном окне ничего не доказывает.** Common memory стёртой
   карты и молчащая шина выглядят одинаково — сплошь `0xFF`. Различает
   только `--cis`: attribute memory с паспортом читается даже у полностью
   стёртой карты. Так же смотрит и ядро: в `drivers/pcmcia/rsrc_nonstatic.c`
   функция `readable()` ради проверки окна вызывает `pccard_validate_cis()`,
   то есть окно считается годным **только если через него читается CIS**;
   резервная `checksum()` отбрасывает содержимое с нулевой суммой (все `0xFF`
   и все `0x00`). Поэтому `no high memory space available` в dmesg означает
   ровно «CIS через окна не читается», а не «карта стёрта».

3. **Нужен доступ к `/dev/mem`.** Если `--probe` пишет `Operation not permitted`,
   в ядре `CONFIG_STRICT_DEVMEM=y`. Тогда добавьте параметр `iomem=relaxed`:

   ```bash
   sudo sed -i 's/^GRUB_CMDLINE_LINUX="\(.*\)"/GRUB_CMDLINE_LINUX="\1 iomem=relaxed"/' \
        /etc/default/grub
   sudo update-grub && sudo reboot
   grep iomem /proc/cmdline          # проверка после загрузки
   ```

4. **8-битная карта на 16-битной шине** отдаёт каждый байт дважды
   (`AA AA BB BB`). Программа это замечает и нормализует, но проверьте: если
   в начале видны осмысленные строки — всё в порядке.
5. **Размер**: окно моста 64 МиБ, карта — 16 или 32 МиБ. Берите `--size 16m`
   или `--size auto`. Лишнее просто зеркалится.
6. Прочитанный образ можно смотреть без карты:
   `python3 pcmcia_gui.py --map-file card.bin`.

# Часть 9. Если что-то не работает

## «Программа не видит карту» — сначала диагностика, потом выводы

```bash
sudo bash ./pcmcia_flash.sh --diag      # или пункт 9 в меню
```

Скрипт проходит цепочку по шагам и говорит, где она рвётся. **«Не видит
карту» — это не диагноз.** Цепочка такая:

```
1. мост CardBus есть и к нему привязан yenta_socket
2. в слоте 16-битная карта (pccardctl status), ядро создало устройство сокета
3. CIS читается (pccardctl ident, /sys/bus/pcmcia/devices/*/prod_id*)
4. pcmciamtd знает окна памяти и Vpp и не падает при опросе
5. появился /dev/mtd0 с правдоподобным размером (16/32 МБ)
```

Обрыв на шаге 1–2 — это **не** CIS: карта либо не подключена, либо ядро не
создало сокет. CIS вообще не при чём, пока слот не отдал карту.

### «no high memory space available» — самая частая причина, и это не CIS

Симптомы вместе: слот карту видит (`pccardctl status` → `5.0V, 16-bit, PC Card`),
а `pccardctl ident` пишет **`no product info available`**, `/sys/bus/pcmcia/devices`
пуст, `/dev/mtd0` нет, в dmesg:

```
pcmcia_socket0: cs: memory probe 0x60000000-0x60ffffff: excluding 0x60000000-0x600fffff
pcmcia_socket0: cs: warning: no high memory space available!
```

Что это значит по порядку причин:

1. Подсистеме PCMCIA нужно «окно памяти» — область адресов, которую она может
   отдать карте. Ядро проверяет кандидатов (те самые `memory probe ... excluding`)
   и забраковало все.
2. Без окна карта **не становится устройством PCMCIA** → `ident` нечего читать →
   `no product info available`.
3. Значит `no product info available` — **следствие** ошибки окон, а не отдельная
   проблема CIS. Пока окна нет, CIS не читается ни у какой карты.
4. `pcmciamtd` при этом вообще не вызывается, поэтому `force_size`, `vpp` и
   `setvpp` сейчас ни на что не влияют.

Что делать, по порядку:

```bash
# 1. Загрузиться с картой, вставленной ДО включения, и сразу посмотреть:
dmesg | grep -iE 'pcmcia|high memory'
#    если предупреждение есть сразу после загрузки — дело в слоте, не в карте

# 2. Контакты: вынуть, протереть, вставить до щелчка

# 3. Трюк со вторым включением (иногда проходит именно на TI PCIxx21):
sudo -i
echo 0 > /sys/class/pcmcia_socket/pcmcia_socket0/card_eject
sleep 2
echo 1 > /sys/class/pcmcia_socket/pcmcia_socket0/card_insert
dmesg | tail -20        # прочитался ли CIS

# 4. Раннее чтение CIS: приём именно для этой ошибки — прочитать CIS до того,
#    как подсистема начнёт раздавать окна
sudo systemctl stop systemd-udevd      # или загрузиться в single-user
#    вставить карту, дождаться строк про CIS в dmesg, затем:
sudo systemctl start systemd-udevd
```

#### Как понять, что дело в слоте, а не в карте

Смотрите, что именно ядро забраковало:

| В dmesg | О чём говорит |
|---|---|
| `cs: memory probe 0x64000000-0x67ffffff: excluding 0x64000000-0x67ffffff` | через это окно ядро не прочитало CIS: не сработала ни `readable()` (ей нужен корректный CIS), ни резервная `checksum()` (она отбрасывает содержимое с нулевой суммой — все `0xFF` и все `0x00`) |
| `cs: IO port probe 0x2400-0x24ff: excluding nothing: probe failed.` | отдельный механизм `do_io_probe()`, карту он не спрашивает: ищет во всём диапазоне наибольшее значение, которое порт выдаёт стабильно на 8 подряд адресах, и вычёркивает всё, что от него отличается |
| память и порты провалены одновременно | **не** доказательство, что карта молчит: 16-битной карте порты обычно не нужны (pcmciamtd работает через память), а Config-регистр CardBus на многих ноутбуках выключен |

Смотреть надо на строки `memory probe`, а решает вопрос только чтение
attribute memory в обход ядра:

```bash
sudo python3 pcmcia_direct.py --cis
```

Кортежи/паспорт читаются → карта жива и отвечает, дело в окнах ядра.
Сплошные `0xFF` или `0x00` → карта или контакт слота не отвечают.

**План Б — отключить саму проверку окон** (диагностический режим):

```bash
echo 'options pcmcia_rsrc probe_mem=0' | sudo tee /etc/modprobe.d/pcmcia-noprobe.conf
sudo update-initramfs -u        # чтобы параметр попал в раннюю загрузку
sudo reboot                     # с картой в слоте
dmesg | grep -iE 'pcmcia|mtd' | tail -20 ; ls -l /dev/mtd*
# вернуть как было:
sudo rm /etc/modprobe.d/pcmcia-noprobe.conf && sudo update-initramfs -u && sudo reboot
```

Параметр `probe_mem` есть **только** у модуля `pcmcia_rsrc` (он же
`pcmcia_core`); у `yenta_socket` и `pcmciamtd` его нет.

Если после этого CIS прочитался и появился `/dev/mtd0` — значит дело было именно
в проверке окон. Окна при этом берутся из `/etc/pcmcia/config.opts` без проверки.

**Решающий опыт:** вставить любую другую 16-битную карту (модем, сетевая, SRAM).
Если и она не видна — виноват слот или мост, а не ваша карта.

Отдельно: у `pcmciamtd` **нет** параметров `mem_base`, `mem_size`, `force_write`.
Если в dmesg есть `pcmciamtd: unknown parameter 'mem_base' ignored` — ядро эти
опции молча выбросило. Допустимые параметры: `bankwidth mem_speed force_size
setvpp vpp mem_type`. Окна памяти задаются не параметрами модуля, а
`/etc/pcmcia/config.opts` и ресурсами сокета.

Если ничего не помогло — сохраните отчёт и пришлите его:

```bash
sudo bash ./pcmcia_flash.sh --diag > diag.txt 2>&1
```

### Если «мост найден, карта в слоте, но /dev/mtd0 нет»

Смотрите вердикт в конце `--diag`. Три типичных случая:

| Что в dmesg | Что это значит | Что делать |
|---|---|---|
| `pcmciamtd: no memory window` | драйверу не дали окно памяти | пункт 2 заново, затем `sudo modprobe -r pcmciamtd; sudo modprobe pcmciamtd` |
| `anonymous` / `no CIS` / `unknown card` | CIS не читается | `force_size=16` (МБ), потом перезагрузить модуль — команды ниже |
| про pcmciamtd вообще пусто | модуль не загружался | `modinfo pcmciamtd`, список `lsmod` (есть ли `pcmciamtd`), ядро i386? |

### Обход для карты без CIS (`force_size`)

```bash
sudo cp -a /etc/modprobe.d/pcmciamtd.conf /etc/modprobe.d/pcmciamtd.conf.bak
sudo sed -i 's/^options pcmciamtd.*/options pcmciamtd vpp=50 setvpp=1 force_size=16/' \
     /etc/modprobe.d/pcmciamtd.conf
sudo modprobe -r pcmciamtd; sudo modprobe pcmciamtd
ls -l /dev/mtd*
```

`force_size` задаётся **в мегабайтах**: `16` = 16 МБ. Если карта на 32 МБ —
ставьте `32`. Размер после этого берётся не из карты, а из настройки, поэтому
**обязательно** сначала снять образ и убедиться, что чтение стабильно и что на
карте не «весь 0xFF» (иначе вы прочитаете пустоту и примете её за данные).

### Если в слоте вообще нет карты по мнению ядра

- `no card` в `pccardctl status` → контакты. Выньте, протрите контакты
  ластиком (без спирта и абразива), вставьте до щелчка, перезагрузитесь с
  картой в слоте.
- `no memory window` в dmesg → слот не отдал окно: повторите шаг 3.2,
  проверьте, не отключён ли слот в BIOS.
- Карта видна как `/dev/sdX` → это ATA-flash или CompactFlash, а не linear
  flash. Тогда MTD не нужен: `sudo mount /dev/sdX1 /mnt` и работайте как с
  флешкой.
- Размер 0 или странный → добавьте в `/etc/modprobe.d/pcmciamtd.conf`:
  `options pcmciamtd vpp=50 setvpp=1 force_size=16`, затем
  `sudo modprobe -r pcmciamtd && sudo modprobe pcmciamtd`.

## Запись не идёт, ошибки стирания

- Скорее всего карта **Intel Series 2 (28F008SA)**: по документации ей 12 В не
  нужны, но часть таких карт всё же требует Vpp — проверяется пробой сектора.
  ноутбуке их нет. Смотрите `PRODID_2` в CIS. Это не лечится программно.
- Проверьте Vpp: должно быть **50**, не 33.
- Протрите контакты карты, перезагрузитесь с картой в слоте.

## «Чтения различаются» при снятии образа

Карта или контакты нестабильны. Что делать по порядку: контакты → перезагрузка
с картой в слоте → прогнать `--blocks` и посмотреть, нет ли оранжевых блоков.
Пока чтения не совпадают — **не записывайте** на эту карту.

## Программа пишет «Нужны права root»

Запускайте через `bash ./gui.sh` (он сам вызовет sudo) или
`sudo python3 pcmcia_gui.py`. Работа без root возможна только на чтение,
и то если настроены права udev (это делает шаг 3.2).

## Графическое окружение не найдено

# Часть 11. Что важно понимать

1. **Карты, которым нужны 12 В на Vpp (28F008SA, 28F016SA, M28F102 и прочие
   28F/Am28F), в слоте ноутбука не пишутся** — 12 В там нет. Am29F016 и
   родственные 5-вольтовые — пишутся, это проверяется пробой сектора. У платы
   Kontron PC/104-PCMCIA-1 12 В могут быть подведены по PC/104 — тогда можно.

### Микросхемы бывают разные (2.15.0)

Один и тот же слот PCMCIA за сорок лет видел очень разные карты, и внутри них
стоят совсем не одинаковые микросхемы. Набор до 2.15.0 был написан «под
Am29F016» — это был один частный случай. Теперь различаются:

| Что именно | Варианты | Что делает набор |
|---|---|---|
| сектор стирания | 16, 32, 64, 128 КиБ | берёт из таблицы/CFI; в адресах карты умножает на число чипов |
| карта секторов | однородная или boot (16K+8K+8K+32K+…+64K) | границы каждого сектора по карте (`span`), см. 2.17.2 |
| команды | байтом (JEDEC) или словом (Intel CUI) | адреса 0x555/0x2AA или 0xAAAA/0x5554, данные словом |
| стирание | 80h/30h (JEDEC) или 20h→D0h (Intel) | отдельные ветки протокола |
| готовность | DQ7/DQ5 (JEDEC) или статусный регистр 70h (Intel) | отдельные проверки, порядок бит WSMS→VPPS→ESS→BWS |
| чипов в карте | 1, 2, 4, 8 | байт i лежит в чипе i % N, команда дублируется в каждый чип |
| питание записи | 5 В или 12 В на Vpp | 12 В берутся со слота; если их нет — честный отказ |

Тип микросхемы набор выясняет в таком порядке: **паспорт карты (CIS) →
идентификатор микросхемы (90h) → CFI (98h) → таблица по имени из `--chip`**.
Если ничего не ответило, печатается «имя не определено» и предлагаются
безопасные значения по умолчанию — без обещаний.

Спросить, что за микросхема, и ничего не испортить:

```bash
sudo python3 pcmcia_direct.py --identify-chip          # паспорт + 90h + 98h
sudo python3 pcmcia_direct.py --chip 28F008SA --no-geometry-check --identify-chip
sudo ./pcmcia_ctl.sh chip                              # пункт 11 в пульте
```

Первая команда подаёт в карту только читающие команды (90h/98h). Вторая не
подаёт вообще ничего — просто пересказывает таблицу, если микросхема уже
известна наверняка.

**Boot-микросхемы (неоднородные секторы).** У Am29F200/400/800B, Am29LV001B/
LV400B/LV800B/LV160D секторы разного размера: 16 КиБ + 2×8 КиБ + 32 КиБ, а
дальше по 64 КиБ (у top-boot — то же в обратном порядке). Набор стирает
**ровно один сектор по карте**, а не «округлением по 64 КиБ». Чтобы выбрать
раскладку, ему нужно знать ревизию: bottom-boot (`…BB`, `…AB`, `…DB`) или
top-boot (`…BT`, `…AT`, `…DT`). Ревизию он берёт из CFI либо из JEDEC ID:

```bash
sudo python3 pcmcia_direct.py --identify-chip                  # покажет карту секторов
sudo python3 pcmcia_direct.py --chip Am29F800BB --write image.bin
sudo python3 pcmcia_direct.py --chip Am29F800BT --write image.bin
```

То же для Fujitsu и ST (у них свои обозначения ревизий): `MBM29F002TC/BC`,
`MBM29F004TC/BC`, `M29F002BT/BB`, `M29F400BT/BB` — `T` в конце означает
top-boot, `B` — bottom-boot. У ST коды устройства `D5h`/`D6h` при вендоре
`20h`; это не те же числа, что у AMD при вендоре `01h`, и набор различает их
по вендору.

Если микросхема молчит и указано имя без ревизии (`--chip Am29F800`), набор
откажется работать и попросит указать BB или BT — это лучше, чем стереть
четыре сектора вместо одного.

**Проверка до стирания.** Перед записью набор стирает крайний сектор и
убеждается, что там 0xFF. Если сектор выбран не тот (16 КиБ вместо 64 КиБ),
микросхема не стирается (нет 12 В) или стирание вообще не идёт — запись
останавливается с кодом 3 и подсказкой. Отключается только ключом
`--no-geometry-check`, и делать это без причины не стоит.

**Про 12 В.** Напряжение программирования не приходит из программы: его
подаёт слот. У ноутбука на контактах Vpp 5 В, поэтому карта на 28F008SA
(Intel CUI, 12 В) в нём не пишется — это ограничение железа. У платы
Kontron PC/104-PCMCIA-1 (контроллер Vadem VG-469, регистры как у Intel
82365SL, порт 03E0h или 03E2h, только 5 В) +12 В на CDVPP1/2 приходят с
разъёма PC/104: если они подведены — Intel-карта пишется, если нет — нет.
Набор в обоих случаях говорит про Vpp прямо, а не «карта не пишется».

### Запись без драйвера (2.14.0)

Когда `/dev/mtdN` нет, писать всё равно можно — командами самой микросхемы:

```bash
sudo python3 pcmcia_direct.py --write-probe          # ПРОБА: один сектор
sudo python3 pcmcia_direct.py --write card.bin       # образ целиком
```

Что происходит при пробе: сектор читается и сохраняется в файл `probe-sector-*.bin`,
стирается, заполняется узором, читается обратно, сравнивается и **возвращается
байт в байт**. Если карта не пишется — образ не трогается, а файл остаётся копией
испорченного сектора.

Ключи: `--chips N` (по умолчанию из паспорта), `--sector N`, `--no-verify`,
`--snapshot-dir КАТАЛОГ`, `--chip ИМЯ`, `--identify-chip`,
`--no-geometry-check`. В пульте это пункты 9, 10 и 11, с Windows —
`fwwrite -Image`, `fwprobe`, `chip` (в меню пункт 11).
   Это ограничение железа, никакая программа его не обойдёт.
2. **Образ — единственная страховка.** Сняли образ, проверили, что два чтения
   совпали, положили в два места. Только потом пишем.
3. **Стирание необратимо.** Слово `ERASE` в диалоге и `YES` в консоли — не
   формальность, а последняя возможность остановиться.
4. **Не выдёргивайте карту во время операции** и не закрывайте программу:
   если закрыть во время записи, карта останется записанной частично.
5. **Ресурс карты не бесконечен.** Каждая запись — это цикл стирания. Поэтому
   программа предупреждает, если образ уже совпадает с картой.
