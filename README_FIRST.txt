ПУЛЬТ УПРАВЛЕНИЯ (быстро, из консоли)
------------------------------------------------------------------
  На ноутбуке (там, где карта):          sudo bash ./pcmcia_ctl.sh
      меню: 1 паспорт и вердикт, 2 снять образ, 3 записать образ,
            4 стереть, 5 сверка файла с картой, 6 можно ли писать,
            7 диагностика окон, 8 полный отчёт

  Без меню, одной командой:
      sudo bash ./pcmcia_ctl.sh info            # паспорт и что можно/нельзя
      sudo bash ./pcmcia_ctl.sh read /root/card.bin
      sudo bash ./pcmcia_ctl.sh write /root/card.bin   (спросит YES)
      sudo bash ./pcmcia_ctl.sh verify /root/card.bin
      sudo bash ./pcmcia_ctl.sh canwrite        # писать ли эту карту вообще

  С Windows-машины, по сети (scp + ssh, ничего вручную не копируется):
      python pcmcia-kit.pyw                    # окно пульта
      python pcmcia-kit.pyw --text             # меню в консоли
      python pcmcia-kit.pyw --text info
      python pcmcia-kit.pyw --text read        # снять и забрать к себе
      python pcmcia-kit.pyw --text write -i card.bin   # отправить и записать
      python pcmcia-kit.pyw --text erase --yes
      python pcmcia-kit.pyw --text diag
      (адрес/пользователь/порт/ключ: --host --user --port -KeyFile)

  Важно про запись: она идёт ТОЛЬКО через драйвер (/dev/mtdN). Если ядро не
  дало карте окно памяти ("unable to map card memory!"), писать нечем —
  пульт скажет это прямо, а не «попробует». Карты с Vpp 12 В (28Fxxx,
  AMD Am29Fxxx) в слоте ноутбука не пишутся даже при живом /dev/mtdN.


ГРАФИЧЕСКАЯ ПРОГРАММА (рекомендуется)
------------------------------------------------------------------
  pcmcia_gui.py   — полноценное окно, 5 вкладок (версия 2.0). Запуск:

        sudo python3 pcmcia_gui.py          (или ./gui.sh — сам спросит пароль)

  В версии 2.4 добавлено:
        * отказ записывать файл, целиком состоящий из 0x00 (классика: выбран
          не тот файл — карта превращалась в нули);
        * предупреждение, если образ уже побайтово совпадает с картой
          (запись ничего не изменит, но сотрёт и запишет заново);
        * в подтверждении записи видно тип содержимого и первые байты образа;
        * горячие клавиши: F1 справка, F5 обновить, Ctrl+R читать,
          Ctrl+W писать, Ctrl+V сверять, Ctrl+M блоки, Ctrl+S отчёт,
          Ctrl+L журнал, Esc отмена;
        * карта блоков сама обновляется после записи/стирания;
        * консоль без графики: --blocks и --map-file <образ>;
        * пункт 1 меню после установки печатает версии пакетов и проверяет,
          что утилиты реально запускаются (ответ на «вроде установилось?»);
        * скрипты работают с флешки FAT32, где у файлов нет бита x;
        * отмена чтения больше не выдаётся за ошибку карты (гонка в Runner);
        * `pcmcia_direct.py` (пункт 11 меню): прямое чтение карты через
          /dev/mem — работает, когда ядро не дало карте окно памяти
          («no high memory space available»). Только чтение;
        * пункт 9 меню и `--diag`: разбор «почему карта не видна» по цепочке
          мост → слот → CIS → драйвер → /dev/mtd, с вердиктом. Раньше на
          «программа не видит карту» приходилось гадать; при этом CIS — только
          третий шаг, до него дело часто не доходит;
        * `--doctor` показывает то же коротко: мост, слот, CIS, вердикт.

  Что нового в 2.0 (по итогам аудита прежней версии):
        * запись теперь стирает ВСЮ карту (флаг -A / flash_erase), а не только
          область под образом — раньше «хвост» карты оставался со старыми данными;
        * любая длинная операция отменяется кнопкой «Отмена»;
        * интерфейс не подвисает: чтение/запись/сверка идут в отдельном потоке,
          окно и прогресс обновляются через очередь событий (раньше Tk вызывался
          из рабочего потока — это могло ронять программу);
        * проверка свободного места до чтения карты в файл;
        * запрет двух запущенных копий одновременно (блокировка /var/lock);
        * проверка «карта защищена от записи» до начала записи;
        * учёт нескольких регионов стирания (16/32 МБ карты);
        * определение формата на карте: пусто / FTL / NFTL — и защита от
          затирания NFTL-карты разметкой FTL;
        * сверка с картой потоковая (не грузит 16 МБ в память, показывает
          первое расхождение);
        * отчёт о каждой операции: TXT + JSON (карта, CIS, версия ядра, результат);
        * проверка, что устройство действительно MTD (иначе — понятный отказ);
        * при ошибке собирается контекст: mtd info, pccardctl, dmesg, lsmod;
        * прогресс по чанкам, карта блоков (стёрт/занят/ошибка, клик по блоку);
        * профиль настроек в ~/.config/pcmcia-flash-tool/profile.json;
        * подтверждение стирания словом ERASE;
        * чтение и запись произвольного диапазона адресов;
        * ротация журнала, проверка PATH на подозрительные каталоги.

  Вкладки:

        устройство, тип MTD, размер, блок стирания, число блоков, модель по CIS

        (например, «карте нужно 12 В — только чтение»);

                Стереть карту, Сделать FAT-диск (FTL), Монтировать/отмонтировать,

        карта всех блоков карты: зелёный — стёрт (0xFF), красный — есть данные,

    «Журнал»

БЫСТРЫЙ СТАРТ (Debian 12 уже установлен, интернет есть)

  1. Скопируйте всю папку на флешку, вставьте в ноутбук, перейдите в неё:
         cd /media/<user>/<флешка>/pcmcia-flash-kit

  2. Проверьте, что система та, что нужно:
         cat /etc/debian_version          -> должно быть 12.x
         uname -r                         -> 6.1.0-XX-686-pae (или 686)
         dpkg --print-architecture        -> i386
         modinfo pcmciamtd | head -5      -> модуль должен найтись

  3. Поставьте утилиты (любой из двух способов):
         sudo apt install mtd-utils pcmciautils pciutils kmod
       или, если сеть отвалится:
         sudo dpkg -i debs/*.deb

  4. Вставьте карту в слот и запустите меню:
         sudo ./pcmcia_flash.sh

     В меню по порядку:
         2) Настроить слот и драйвер      <- один раз, Vpp спросит (жмите 1 = 5 В)
         3) Показать состояние карты      <- должен появиться /dev/mtd0 с размером 16/32 МБ
         4) Снять образ карты             <- СНАЧАЛА ЭТО, обе карты, обе сохранить
         6) Записать образ на карту       <- по одному, с верификацией
         8) Тест записи                   <- по желанию, проверяет, что карта вообще пишется
         0) выход

  Если файловая система флешки смонтирована с noexec и скрипт не запускается:
         sudo bash ./pcmcia_flash.sh


ГЛАВНОЕ ПРЕДУПРЕЖДЕНИЕ ПРО Vpp (напряжение программирования)

  16-битные карты бывают двух видов, и это определяет, сможете вы писать или нет:

    * Intel Series 2 (28F008SA) — 5-вольтовая серия по документации, но часть
      таких карт разводит Vpp на 12 В. В ноутбуке 12 В на pin 18 НЕ РАЗВЕДЕНО
      (максимум 5 В) — ограничение железа, а не Linux. Маркировка: "SERIES2-XX".
    * Intel Series 2+ / Value Series 100 / AMD / Catalyst / Sharp — пишутся от 5 В.
      Маркировка: "SERIES2+" или "S2E8 SW". Это нормальный рабочий вариант.

  Как узнать: в меню пункт 9 (или  sudo ./linux/flashcard.sh ident).
  Смотрите строку PRODID_2 и наклейку на карте.

  В меню пункт 2 спрашивает Vpp:
     1 = 5.0 В  — правильный выбор в 95% случаев;
     2 = 3.3 В  — только если карта ТОЧНО рассчитана на 3.3 В.
  Ставить 12 В нельзя: на этом ноутбуке их нет, а ошибка с Vpp может
  повредить карту.

  Если карта оказалась 12-вольтовой (28Fxxx / Am28Fxxx) — только чтение.
  Am29F016 и подобные 5-вольтовые пишутся в слоте: набор проверяет это
  пробной записью ОДНОГО сектора со сверкой.

  МИКРОСХЕМЫ БЫВАЮТ РАЗНЫЕ (с 2.15.0)
  -----------------------------------
  Раньше набор был написан «под Am29F016»: сектор 64 КиБ, команды байтом,
  два чипа. Это только один из вариантов. В карточках того времени стоят:

      Am29F016/032/080/040, Am29LV016/LV800, MBM29F016 - JEDEC, сектор
          64 КиБ, 5 В (LV - 3 В), команды байтом: AA/55, A0, 80/30, DQ7/DQ5;
      M28F102 - JEDEC, но сектор 16 КиБ и нужно 12 В на Vpp;
      28F008SA / 28F016SA / 28F016S5 - Intel CUI: команды СЛОВОМ (20h/D0h
          стирание, 40h запись), статус читается регистром (70h), блок
          128 КиБ, нужно 12 В на Vpp. Команды «стереть весь чип» у них нет.

  Что теперь делает набор:
    * число микросхем в карте - 1, 2, 4, 8 (байт i лежит в чипе i % N);
    * сектор берётся из таблицы и умножается на число чипов - иначе стирание
      «одного сектора» задевало бы соседний;
    * тип определяется по паспорту карты и по ответу самой микросхемы
      (90h - идентификатор, 98h - CFI), а не «на глаз»;
    * если оба источника молчат, набор говорит прямо «тип не определён» и
      предлагает --chip, а не пишет наугад;
    * перед записью тип ПРОВЕРЯЕТСЯ стиранием крайнего сектора.

      sudo python3 pcmcia_direct.py --identify-chip    # только опрос, НЕ пишет
      sudo python3 pcmcia_direct.py --chip M28F102 --identify-chip   # из таблицы
      sudo ./pcmcia_ctl.sh chip                        # то же из пульта (пункт 11)

  ВАЖНО ПРО НАПРЯЖЕНИЕ. 12 В на Vpp берутся не из программы, а из слота.
  У ноутбука их нет: карта с 28F008SA в нём не пишется (и это сказано по
  имени микросхемы, а не «карта плохая»). У платы Kontron PC/104-PCMCIA-1
  (контроллер Vadem VG-469, порт 3E0h или 3E2h, только 5 В) +12 В на
  CDVPP1/2 приходят с разъёма PC/104 - если они подведены, Intel-карта
  пишется там, а без них - нет.

  ЗАПИСЬ БЕЗ ДРАЙВЕРА (с 2.14.0)
  -------------------------------
  Ядро не даёт вашей карте /dev/mtdN, поэтому flashcp писать некуда. Теперь
  набор умеет писать МИМО ядра: команды JEDEC (AA/55, A0 программирование,
  80/30 стирание, опрос DQ7/DQ5) подаются прямо в микросхему через то же
  окно моста, которым набор читает образ.

      sudo python3 pcmcia_direct.py --write-probe           # ПРОБА: 1 сектор
      sudo python3 pcmcia_direct.py --write card.bin        # запись образа

  Проба читает сектор, сохраняет его в файл, стирает, заливает узор
  (0x00/0xFF/0x55/0xAA и 0..255), сверяет и ВОЗВРАЩАЕТ исходные байты.
  Если карта не пишется - образ не трогается, а файл с исходными байтами
  остаётся. Проба - единственный честный ответ на вопрос «пишется ли»,
  пока /dev/mtdN нет. Порядок: проба -> и только потом запись.
  Обходной путь для 12-вольтовых: программатор или старый ноутбук с реальными
  12 В на слоте.


ПЕРВЫЙ ЗАПУСК: ЧТО ДОЛЖНО БЫТЬ НА ЭКРАНЕ

  После пункта 2:
      мост: 00:0c.0 CardBus bridge: Texas Instruments PCIxx21/x515 ...
      /etc/pcmcia/config.opts:
          include memory 0xa2000000-0xa3ffffff
          include memory 0xa4000000-0xa40fffff
          include port 0x00003000-0x000030ff
          include port 0x00003400-0x000034ff
      (адреса у вас будут свои — скрипт берёт их из lspci автоматически)

  После пункта 3:
      карта распознана как /dev/mtd0
      mtd.type = MTD_NORFLASH
      mtd.size = 16777216 (16M)   или   33554432 (32M)
      Socket 0: 5.0V 16-bit PC Card ... bound to driver "pcmciamtd"

  Если /dev/mtd0 НЕ появился — скрипт сам печатает список причин.
  Самые частые:
      а) карта не до конца вставлена / окисленные контакты;
      б) карта — ATA-flash или CompactFlash, а не linear flash
         (тогда она видна как /dev/sdX, и нужен не mtd, а обычный mount);
      в) размер не читается из CIS — добавьте в /etc/modprobe.d/pcmciamtd.conf:
             options pcmciamtd mem_type=0 bankwidth=2 force_size=4
         для карты 4 МиБ (2 x Am29F016); для 16/32-мегабайтных force_size=16/32.
         Затем: sudo modprobe -r pcmciamtd && sudo modprobe pcmciamtd
         Параметры vpp=/setvpp= без даташита конкретного чипа НЕ ставить:
         документация ядра прямо предупреждает, что так можно повредить карту.
         С 5-вольтовыми картами (Am29F016) они не нужны.
      г) 8-битная карта — добавьте bankwidth=1; SRAM — mem_type=1; ROM — mem_type=2;
      д) совсем «анонимная» карта без CIS — нужен CONFIG_MTD_PCMCIA_ANONYMOUS=y,
         то есть пересборка модуля (в дефолтном ядре Debian он выключен).
         Редкий случай; если попадёте — скажите, соберём модуль отдельно.

  TI PCIxx21 иногда не подхватывает 16-битную карту «на горячую».
  Если пункт 3 упорно не видит карту — оставьте карту в слоте и перезагрузитесь,
  потом сразу пункты 2 и 3.


ЧТО ДЕЛАТЬ С ОБРАЗАМИ

  * Образ 16 МБ = 16777216 байт, 32 МБ = 33554432 байта. Это и есть «дамп карты».
  * Пункт 4 читает карту ДВАЖДЫ и сравнивает: если чтения различаются —
    карта или контакты нестабильны, писать на неё нельзя.
  * Храните образы в трёх местах (флешка, диск ноутбука, любая другая машина).
    Файл .md5 создаётся рядом автоматически.
  * Запись (пункт 6) всегда: стереть -> записать -> прочитать назад и сравнить.
  * Если нужны ФАЙЛЫ и FAT, а не сырой образ — пункт 7 (FTL + mkfs.vfat).


ЕСЛИ ХОЧЕТСЯ БЕЗ МЕНЮ

  sudo ./linux/setup_linear_flash.sh        # 5 В
  sudo ./linux/setup_linear_flash.sh 33     # 3.3 В

  sudo ./linux/flashcard.sh ident

ЕСЛИ КАРТУ НУЖНО СНЯТЬ, А НОУТБУК СЕЙЧАС С WINDOWS

  Windows 7 и новее 16-битные linear flash не читают. Поэтому:
    1) скачайте 32-битный live-Linux (antiX 23 i386, Puppy, Alpine x86);
    2) запишите на флешку (Rufus) и загрузитесь с неё;
    3) работайте по этой же инструкции.
  Если загрузиться не с чего — можно снять «сырой» дамп карты, пока она стоит
  в Windows-ноутбуке, через Linux-флешку на ЛЮБОМ другом компьютере с PCMCIA-слотом
  (см. windows/card_dump.linux.sh). На самом V2030D под Windows это не заработает.


ПРИЗНАКИ ХОРОШЕГО ФИНАЛА

  * mtd.size совпадает с наклейкой на карте;
  * два чтения подряд дают одинаковый md5;
  * erase проходит без ошибок (нет "erase failed" / "MTD Erase failure");
  * после write обратное чтение совпадает с исходным файлом байт в байт;
  * карта, вставленная в целевое устройство (прибор/маршрутизатор/ПЛК), им принимается.
