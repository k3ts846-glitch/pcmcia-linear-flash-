ТЕСТЫ НАБОРА PCMCIA FLASH KIT 2.16.0
====================================
Пять наборов, около 1000 проверок, плюс A/B-тест на 7 сценариев.
Точное число зависит от среды: с PowerShell и графикой — 703 + 74 + 99 + 72.
Без PowerShell test_scripts.py даёт меньше (часть проверок про Windows-скрипты).
Реальная карта НЕ нужна и не затрагивается.

ВРЕМЯ ПРОГОНА (2.16.0)
----------------------
    test_scripts.py            около 32 с   (полный)
    test_scripts.py --fast     около 17 с   (без двух долгих наборов)
    test_v2.py                 около 5 с
    test_gui.py                около 15 с
    test_ui_pro.py             около 5 с

Быстрый режим сделан для того, чтобы прогонять набор после каждой правки:
он пропускает t_flash_write и t_chip_geometry (запись 8 МиБ на модели).
Перед выпуском архива прогоняется полный режим.

Запись без драйвера проверяется на модели карты (tests/nor_model.py).
Модель знает РАЗНЫЕ микросхемы: JEDEC (Am29F016, M28F102 с сектором 16 КиБ) и
Intel CUI (28F008SA: команды словом, статусный регистр, VPPS без 12 В, ESS/BWS),
1, 2 и 4 чипа. Команды принимаются только в правильном порядке, NOR чистится
только 1 -> 0, стирание действует на тот чип, куда попал адрес, побайтовая
команда на Intel-карте считается ошибкой. Модель нарочно придирчивая - на ней
нашлись девять настоящих дефектов протокола, которые «мок, который всё
принимает» пропустил бы.

    sudo apt install -y xvfb            # если на машине нет графики
    xvfb-run -a python3 tests/test_v2.py       # 99 проверок — аудит + регрессия
    xvfb-run -a python3 tests/test_gui.py      # 74 проверки — утилиты и интерфейс
    xvfb-run -a python3 tests/test_ui_pro.py   # 72 проверки — отзывчивость, скорость, защита
    python3 tests/test_scripts.py             # 703 проверки — консольные скрипты
                                              # (без PowerShell — 600)
    python3 tests/test_scripts.py --fast      # то же, но вдвое быстрее
    python3 tests/test_win.py                 # 107 проверок — пульт на Python
                                              # (поддельные ssh/scp, сеть не нужна)
    python3 tests/release.py                  # проверки перед сборкой архива
    python3 tests/release.py --build           # собрать ZIP, tar.gz и суммы
    python3 tests/ab_regression.py pcmcia_gui.py   # A/B: 7 сценариев, X не нужен

Ожидаемый финал у каждого: «ИТОГО: прошло N, провалено 0 / ВСЕ ТЕСТЫ ПРОЙДЕНЫ».

Как устроено: вместо /dev/mtd0 подставляется обычный файл 16 МБ, а утилиты
mtd_debug, flashcp, flash_erase, pccardctl, lspci заменяются заглушками во
временной папке (в PATH). Заглушка flashcp ведёт себя как настоящая:
без -A стирает только область под образ, с -A — всю карту. Именно поэтому
тест на «хвост» карты имеет смысл.


tests/test_v2.py — по пунктам аудита (18 групп)
  P0-1  потокобезопасность: статический разбор кода — ни одна фоновая функция
        не обращается к виджетам Tk; события идут через queue.Queue
  P0-2  запись стирает «хвост» карты; без этого режима хвост сохраняется
        и программа об этом предупреждает
  P0-3  отмена чтения по кнопке -> Cancelled, недописанный файл не выдаётся
        за готовый образ
  P0-4  нехватка места обнаружена ДО чтения, файл не создан
  P0-5  второй экземпляр программы получает отказ (flock), после закрытия —
        снова можно
  P0-6  карта с WP -> отказ и для стирания, и для теста записи
  P0-6b разбор флагов mtd_debug: MTD_CAP_NORFLASH не блокирует запись
        (проверка на ложное «карта защищена»)
  P1-7  несколько регионов стирания -> предупреждение
  P1-8  формат карты: пусто / FTL / NFTL / нули / неизвестно; NFTL блокирует
        разметку FTL
  P1-9  потоковая сверка: совпадение проходит, подменённый байт найден,
        указано место расхождения
  P1-10 отчёт: TXT + JSON, внутри карта, CIS, хост, операция
  P1-11 проверка «это MTD»: файл-тренировка разрешена и объявлена,
        не-MTD устройство — отказ
  P1-12 контекст ошибки: mtd info, pccardctl, dmesg, lsmod, статистика
  P2-13 прогресс: много вызовов, доходит до 100, не «прыгает» назад
  P2-14 карта блоков: число блоков, занятые/стёртые различаются верно
  P2-15 профиль настроек: сохранение и чтение
  P2-18 PATH: world-writable каталог обнаружен, нормальный PATH — чисто
  P2-20 диапазон адресов: чтение нужной длины, выход за карту отклонён
  GUI   дымовой тест: окно, 5 вкладок, состояние, очередь событий
        (лог и прогресс доходят до экрана), отрисовка карты блоков и hex

  R1-R9 регрессия второго аудита (тесты, которые ПАДАЛИ на версии 2.0):
  R1  утилита пишет меньше, чем просили (rc=0) -> образ не усечён, мусора нет
  R2  сверка пустого и несуществующего файла отвергается
  R3  короткое чтение при сверке -> ошибка, а не «совпало»
  R4  место на диске считается под двойное контрольное чтение
  R5  запись диапазона не отправляет на карту обрывок файла
  R6  утилита с выводом 700 КБ не подвешивает программу (был дедлок)
  R7  недопустимое Vpp (12 В, опечатка) отвергается
  R8  смонтированное устройство не даёт писать мимо файловой системы
  R9  в диалог ошибки не выливается весь контекст dmesg


tests/test_gui.py — утилиты и интерфейс (10 групп)
  1  классификация карт по CIS (Series 2 / 2+ / Value / AMD / SRAM / неизвестно)
  2  форматирование размеров
  3  MD5 и подсчёт по части файла
  4  состояние карты: размер, блок стирания, тип MTD, MANFID, режим тренировки
  5  поведение без карты
  6  чтение в файл (+ .md5), запись со стиранием, сверка, стирание
  7  разбор окон слота из lspci, запись config.opts / modprobe.d / udev
  8  целостность GUI: вкладки, состояние, кнопка отмены
  9  автопоиск офлайн-пакетов: папка debs/, архив tar.gz, отсутствие пакетов
 10  PATH и защита от второго экземпляра

  S9  linux/pcmcia_flash.py --selftest работает без карты
  S10 интерактивное меню из stdin: пункт 6 -> запись со стиранием -> сверка

  S19 pcmcia_direct.py --cis: разбор CIS (кортежи, MANFID, VERS_1, тип FLASH и

ЧЕГО ЭТИ ТЕСТЫ НЕ ПРОВЕРЯЮТ
  Реальную карту: тайминги, Vpp, поведение pcmciamtd на TI PCIxx21 и ошибки
  стирания конкретной микросхемы. Это проверяется только на ноутбуке —
  первым делом «Идентификатор (CIS)», затем «Тест записи (0xFF)».
