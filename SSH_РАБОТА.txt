РАБОТА ПО SSH — ОДИН ЗАПУСК НА ВАШЕМ КОМПЬЮТЕРЕ
===============================================

Как это устроено: подключиться к вашему ноутбуку я не могу — моя сторона
не имеет маршрута в вашу сеть. Поэтому подключается не «я», а ВАШ скрипт:
он сам заходит по SSH на ноутбук, запускает там проверки и приносит отчёт
обратно сюда, к вам. Вам остаётся запустить одну команду и прислать файл.

Пароль root нигде не сохраняется: его спрашивает сам ssh (а если вы входите
обычным пользователем — ещё и sudo на ноутбуке). В файлы и в командную
строку пароль не попадает.


САМЫЙ КОРОТКИЙ ПУТЬ (рекомендуется)
-----------------------------------
На ТЕКУЩЕМ компьютере (там, где открыт этот чат), в папке набора:

    bash remote_collect.sh

Что произойдёт:
  1) проверит ssh и файлы набора;
  2) отправит набор на 192.168.0.94 в /tmp/pcmcia-collect;
  3) запустит там ./collect_all.sh (через sudo, если вошли не root);
  4) вернёт отчёт сюда: otchet-192.168.0.94-<дата>.txt;
  5) уберёт за собой временную папку на ноутбуке (отчёт там остаётся:
     /tmp/otchet-pcmcia.txt — его можно удалить).

Один раз спросит пароль. Дальше — пришлите полученный файл в переписку.

Если что-то не так с адресом/пользователем:

    bash remote_collect.sh 192.168.0.94                  # адрес можно так
    bash remote_collect.sh user@192.168.0.94             # обычный пользователь
    bash remote_collect.sh --user логин --host 192.168.0.94 --port 2222
    bash remote_collect.sh 192.168.0.94 --kit /путь/к/pcmcia-flash-kit
    bash remote_collect.sh 192.168.0.94 --image --pull-image   # + снять образ
                                                              #   и забрать его к себе
    bash remote_collect.sh 192.168.0.94 --dry-run        # только показать план,
                                                          # ничего не подключать

Проверка без запуска (ничего не трогает): bash remote_collect.sh --dry-run


ИЗ WINDOWS (PowerShell)
-----------------------
То же самое, только другой скрипт — remote_collect.py:

    cd D:\pcmcia-flash-kit
    python remote_collect.py                                  # 192.168.0.94, root
    python remote_collect.py --user alex                       # обычный пользователь
    python remote_collect.py --host 192.168.0.94 --port 2222
    python remote_collect.py --kit 'D:\pcmcia-flash-kit'
    python remote_collect.py --image --pull-image                # + снять образ и забрать
    python remote_collect.py --dry-run                          # только показать план

Что нужно в Windows:
  * ssh и scp уже есть в Windows 10 1803+ и Windows 11.
    Если ssh нет, в PowerShell от администратора:
      Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0
  * на ноутбуке должен работать ssh-сервер.

Три вещи, о которых стоит знать заранее (проверено):
  1) адрес задаётся ключом --host, потому что $Host в PowerShell — это
     зарезервированная переменная (имя компьютера), а не адрес;
  2) пароль ssh спрашивает один раз за запуск (весь цикл уложен в один
     сеанс). Если хочется вообще без пароля — настройте ключ:
       ssh-keygen -t ed25519
       type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@192.168.0.94 "cat >> ~/.ssh/authorized_keys"
     и скопируйте публичный ключ командой ssh-copy-id (в Git Bash) или
     указанной строкой;
  3) запускайте из обычного окна PowerShell, а не из PowerShell ISE:
     в ISE ssh не может спросить пароль с клавиатуры.

Что должно быть:
  * на текущем компьютере: ssh и scp (Debian/Ubuntu: sudo apt install
    openssh-client; Windows — встроенный OpenSSH, см. ЧТО_НУЖНО_НА_WINDOWS.txt);
    и РЯДОМ СО СКРИПТОМ файлы набора: collect_all.sh, pcmcia_direct.py
    (обязательно), pcmcia_flash.sh (добавляет разделы --selftest и --diag),
    pcmcia_gui.py (чтобы открыть снятый образ);
  * на ноутбуке: включён ssh-сервер (sudo apt install openssh-server,
    systemctl enable --now ssh) и вы знаете пароль пользователя;
  * файлы collect_all.sh, pcmcia_direct.py лежат рядом с remote_collect.sh.

Пароль root в переписку присылать НЕ нужно и не надо: он останется в чате
навсегда, а нужен только вашей машине.


ЕСЛИ SSH С ТЕКУЩЕГО КОМПЬЮТЕРА НЕДОСТУПЕН
-----------------------------------------
Тогда — вручную, в сеансе SSH на ноутбуке (то же самое делает
collect_all.sh, но одной командой):

    sudo -i
    cd /media/*/*/pcmcia-flash-kit
    bash ./report.sh       # или sudo bash ./collect_all.sh

и прислать файл report-*.txt / otchet-*.txt.




ПОДГОТОВКА (один раз)
---------------------

ПОДРОБНОСТИ ПО collect_all.sh (это то, что выполняется на ноутбуке)
-------------------------------------------------------------------
    sudo bash ./collect_all.sh                  # полная диагностика
    sudo bash ./collect_all.sh --image          # + снять образ в /root/card.bin
    sudo bash ./collect_all.sh --no-slow        # без --selftest и --diag (быстро)
    sudo bash ./collect_all.sh --out /root/otchet.txt

Образ снимается ТОЛЬКО если в разделе 7 прочитан паспорт карты
(там так и написано: «ИТОГ РАЗДЕЛА 7: паспорт прочитан: ДА/НЕТ»).

ШАГ 1. ОДИН ОТЧЁТ ЦЕЛИКОМ (30 секунд)
--------------------------------------
    bash ./report.sh

На выходе: строка "Файл: <путь>/report-<дата>.txt" и тот же текст на экране.
Пришлите файл или скопируйте экран. В отчёте четыре раздела:

    1. ОКРУЖЕНИЕ       — ядро, архитектура, root, md5 файлов набора
    2. ЯДРО, СЛОТ      — мост, слот, окна, /dev/mtd*, dmesg про pcmcia
    3. ОКНА ПАМЯТИ     — pcmcia_direct.py --probe
    4. ПАСПОРТ КАРТЫ   — pcmcia_direct.py --cis  (главный раздел)

Если нужен только один раздел:

    bash ./report.sh --step cis
    bash ./report.sh --step diag

Отчёт пишется рядом со скриптом; если флешка смонтирована только на чтение —
в /var/tmp/report-<дата>.txt. Можно задать явно:

    bash ./report.sh --out /root/otchet.txt


ШАГ 2. ЧТО ЧИТАТЬ В РАЗДЕЛЕ 4 (это решает вопрос «жива ли карта»)
------------------------------------------------------------------
Ищите одну из трёх картин:

  А) "Кортежи CIS (N):" + строки CISTPL_DEVICE / CISTPL_MANFID /
     "производитель карты ... продукт ... размер из DEVICE ..."
        -> карта ЖИВА, паспорт читается. Дело в окнах ядра, не в карте.
        Следующий шаг: снятие образа (шаг 3).

  Б) "attribute memory = сплошные 0xFF: карта НЕ отвечает."
        -> ноль ответов там, где обязан быть паспорт. Контакты/посадка/
           другая карта. Стирание тут ни при чём.

  В) "attribute memory = сплошные 0x00" — карта тоже не отвечает.

  Г) "нет цепочки кортежей, и содержимое не однородное" — карта что-то
     отдаёт, но не паспорт: возможно, это не linear flash. Пришлите
     первые 64 байта из отчёта.


ШАГ 3. СНЯТИЕ ОБРАЗА (только если раздел 4 дал вариант А)
---------------------------------------------------------
    python3 pcmcia_direct.py --read /root/card.bin --double --size auto

  --double      два чтения и сверка; при расхождении образ НЕ сохраняется
  --size auto   размер по повторению адресных линий (карта 16 или 32 МиБ)
  если auto ошибётся: --size 16m или --size 32m

В конце печатается размер, md5 и вердикт по началу карты. Пришлите эти
строки — по ним видно, есть ли на карте данные вообще.


ЧТО ПРИСЫЛАТЬ
-------------
* лучше файл отчёта целиком: report-*.txt (в нём есть md5 файлов набора,
  так я вижу, что у вас именно та сборка);
* если копируете экран — копируйте раздел целиком, не по одной строке;
* не нужно присылать пароли, ключи, содержимое /etc/shadow и т.п.;
* вывод длиной в сотни строк режьте так: bash ./report.sh --step cis


ЧАСТЫЕ ЗАМИНКИ
--------------
  "нет lspci"          -> sudo apt install pciutils (или пункт 1 меню)
  "нет pccardctl"      -> sudo apt install pcmciautils
  "нужен root"         -> sudo -i перед запуском
  "не могу писать в..." -> bash ./report.sh --out /var/tmp/otchet.txt
  отчёт пустой в разделах 3-4 -> запускали без sudo
