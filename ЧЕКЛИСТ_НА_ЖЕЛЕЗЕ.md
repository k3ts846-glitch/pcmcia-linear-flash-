# Чек-лист первого запуска на AMILO Pro V2030D

Печатать/держать рядом. 12 шагов, на каждом: что делать, что должно быть,
что делать при отклонении. Занимает ~20 минут.

Перед началом: карта в слоте (лучше вставленной до загрузки), система
Debian 12 i386, набор распакован, вы в консоли.

---

### Шаг 0. Проверка системы

```bash
cat /etc/debian_version        # ожидается 12.x
dpkg --print-architecture      # ожидается i386 (НЕ amd64)
uname -r                       # 6.1.0-XX-686-pae
```

**Должно быть:** `12.x`, `i386`, ядро `686` или `686-pae`.
**Если `amd64`** — стоит 64-битная система: pcmciamtd работать не будет,
нужна переустановка i386.

---

### Шаг 1. Автопроверка набора

```bash
cd pcmcia-flash-kit
python3 pcmcia_gui.py --selftest
```

**Должно быть:** `Архитектура: i386`, `tkinter: есть`, `PATH: ок`,
`Устройство: /dev/mtd0 — найдено (MTD)`.

**Если карта не найдена** — это ещё не отказ, идём к шагу 2–3.
**Если `PATH: риск: ...`** — продолжать можно, но не запускайте от root
программы из каталога, доступного на запись всем.

---

### Шаг 2. Утилиты

```bash
sudo apt install -y mtd-utils pcmciautils pciutils kmod python3-tk
# без интернета:
sudo dpkg -i debs/*.deb && sudo apt-get -f install -y
```

**Должно быть:** все команды завершились без `E:`.
**Проверка:** `mtd_debug --version`, `pccardctl --version` отвечают.

---

### Шаг 3. Слот и драйвер

```bash
sudo python3 pcmcia_gui.py      # вкладка «Настройка» -> «Настроить слот и загрузить драйверы»
```
или
```bash
sudo ./linux/setup_linear_flash.sh 50   # Vpp 5.0 В
```

**Должно быть:** найден мост `CardBus bridge: Texas Instruments PCIxx21`,
записаны окна памяти, `modprobe` без ошибок.
**Если «CardBus-мост не найден»** — слот отключён в BIOS (раздел
Advanced/PCI): включить, перезагрузиться.

---

### Шаг 4. Появился ли /dev/mtd0

```bash
sudo python3 pcmcia_gui.py --doctor
```

**Должно быть:**
```
/dev/mtd0 — найдено (MTD)
  размер: 16777216 (16.00 МиБ)   или 33554432 (32.00 МиБ)
  блок: 131072 / 262144, регионов 1
  модель: Intel Series 2+ / Value   (или иная из CIS)
```

**Если «не найдено»:**
1. `pccardctl status` — карта видна в слоте? Если `no card` — контакты.
2. `dmesg | tail -30` — есть строки `pcmciamtd`? Если `no memory window` —
   вернуться к шагу 3.
3. `lspci -nnv | grep -A5 CardBus` — окна памяти выданы?
4. Карта может быть ATA-flash/CF: тогда она видна как `/dev/sdX`, и это
   другой сценарий (`mount`, а не mtd).

---

### Шаг 5. Идентификатор карты (важнейший шаг)

В GUI: «Идентификатор (CIS)». Или:
```bash
sudo pccardctl ident
```

**Смотрим `PRODID_2`:**
- `SERIES2-02`, `SERIES2-01` → **Intel Series 2, нужно 12 В → только чтение**
- `SERIES2-20`, `S2E8` → Series 2+ / Value → **пишется**
- `VALUE 100` → пишется
- `AMD`, `Am29F` → пишется
- пусто → карта «анонимная», вероятно нужен `force_size`

**Это определяет всё дальнейшее.** Если карта 12-вольтовая — шаги 9–10
не будут работать, и это не лечится.

---

### Шаг 6. Проверка записи без риска

В GUI: «Тест записи (0xFF)» (стирает карту целиком — только если там нет
нужных данных!). Если данные нужны — шаг 7 обязателен до него.

**Должно быть:** `Тест записи пройден`.
**Если «Сверка: N различий»** — карта пишется нестабильно:
- проверить Vpp (должно быть 50, не 33);
- протереть контакты карты ластиком/спиртом;
- попробовать перезагрузку с картой в слоте.

---

### Шаг 7. Снять образы (обязательно до любой записи)

```bash
sudo ./linux/flashcard.sh backup /root/card16_original.bin
```
или в GUI: «Прочитать карту в файл…»

**Должно быть:** `OK: два чтения совпали, образ стабилен`, создан `.md5`.
**Если «чтения различаются»** — карта или контакты нестабильны. Писать на неё
нельзя, пока не разберётесь. Файл `.check` оставлен для сравнения.

**Сохраните образ в двух местах** (диск ноутбука + флешка). Это единственная
страховка.

---

### Шаг 8. Записать образ

GUI: «Записать образ на карту…», галочка «Стереть всю карту перед записью»
включена. Или:
```bash
sudo ./linux/flashcard.sh write /root/new16.bin
```

**Должно быть:** `Стирание всей карты... Запись завершена... OK: карта
совпадает с файлом`.

---

### Шаг 9. Отдельно проверить «хвост»

Если писали образ меньше карты:
```bash
sudo mtd_debug read /dev/mtd0 <конец-512> 512 /tmp/tail.bin
xxd /tmp/tail.bin | tail -3
```

**Должно быть:** всё `0xff`. Если видите старые данные — стирание не
сработало, сообщите мне.

---

### Шаг 10. Если нужен «просто диск» (FAT)

GUI: «Сделать FAT-диск (FTL)…» — **стирает карту**.
```bash
sudo ftl_format -i /dev/mtd0
sudo modprobe ftl
sudo mkfs.vfat /dev/ftl0
sudo mkdir -p /mnt/card && sudo mount /dev/ftl0 /mnt/card
```

**Перед выдёргиванием карты:** `sudo umount /mnt/card` — иначе потеря данных.

---

### Шаг 11. Что прислать мне

Достаточно трёх файлов (или их текста в сообщении):

```bash
sudo python3 pcmcia_gui.py --doctor > doctor.txt 2>&1
sudo dmesg | tail -60 > dmesg.txt
sudo mtd_debug info /dev/mtd0 > mtinfo.txt 2>&1
```

Плюс: на каком шаге что пошло не так и что было на экране.

По этим трём файлам видно: распозналась ли карта, какой у неё тип, есть ли
write-protect, сколько регионов, и что говорит ядро. Дальше я скажу
конкретно, что делать — без угадывания.

---

### Быстрая шпаргалка «симптом → причина»

| Симптом | Вероятная причина | Куда смотреть |
|---|---|---|
| `/dev/mtd0` нет, `pccardctl status` = no card | контакты / слот в BIOS | шаги 3–4 |
| `/dev/mtd0` есть, размер 0 или странный | CIS не читается | `force_size=16` в `/etc/modprobe.d/pcmciamtd.conf` |
| запись падает на erase | карта 12 В (Series 2) или Vpp | шаг 5, 6 |
| чтение нестабильно (два чтения различаются) | контакты, питание | шаг 7 |
| `flashcp` пишет меньше, чем надо | сбойные блоки | «Блоки» в GUI — оранжевые блоки |
| после записи «хвост» не 0xFF | стирание не выполнялось | шаг 9, сообщите мне |
