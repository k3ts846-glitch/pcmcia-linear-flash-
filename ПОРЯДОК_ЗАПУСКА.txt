ПОРЯДОК ЗАПУСКА — ЧТО И КОГДА ЗАПУСКАТЬ
=======================================

Ситуация: карта в слоте, слот её видит, но ядро пишет
"cs: warning: no high memory space available!" и /dev/mtd0 не появляется.
Ниже — строго по шагам, от копирования файлов до чтения карты.

Все команды выполняются ИЗ ПАПКИ НАБОРА на флешке:
    cd /media/<пользователь>/<метка флешки>/pcmcia-flash-kit
Если не знаете путь: lsblk, потом cd по найденной точке монтирования.

ВАЖНО про флешку FAT32: у файлов нет бита исполнения, поэтому
    bash ./pcmcia_flash.sh        ЗАПУСТИТСЯ
    ./pcmcia_flash.sh             НЕ запустится (Permission denied)
Python-файлы запускаются как обычно: python3 pcmcia_direct.py ...


ШАГ 1. СКОПИРОВАТЬ ФАЙЛЫ (один раз)
-----------------------------------
Из папки "полные-файлы" на флешку, сохранив структуру:

    pcmcia_gui.py, pcmcia_direct.py, pcmcia_flash.sh,
    README_FIRST.txt, ИНСТРУКЦИЯ.md, AUDIT_2.4.txt   ->  корень набора
    linux/flashcard.sh                               ->  linux/
    tests/*.py, tests/README_TESTS.txt               ->  tests/
    pcmcia-kit.pyw, pyproject.toml, README.md        ->  корень набора
    src/pcmcia_kit/                                  ->  src/pcmcia_kit/
    PCMCIA_LINEAR_FLASH_СПРАВОЧНИК.md                ->  корень набора

Ничего запускать не нужно. debs/, demo/, gui.sh не копируются — не менялись.


ШАГ 2. УБЕДИТЬСЯ, ЧТО НАБОР ЦЕЛ (20 секунд, root не нужен)
----------------------------------------------------------
    bash ./pcmcia_flash.sh --selftest      проверка окружения и утилит
    bash ./pcmcia_ctl.sh selftest          проверка самих тестов набора
                                           (--full - полный прогон, ~1 минута)

Ожидаемо: "Каталог скрипта", "Архитектура: i386", "Количество .deb: 72",
"Модуль pcmciamtd: /lib/modules/.../pcmciamtd.ko", список утилит с "+".
Если архитектура amd64 — дальше идти нет смысла, нужна 32-битная система.


ШАГ 3. ОДИН ОТЧЁТ ВМЕСТО ПЯТИ КОМАНД (30 секунд)
-------------------------------------------------
Вариант А — вы работаете С ТЕКУЩЕГО компьютера и ноутбук в сети
(например 192.168.0.94). Скрипт сам сходит туда по SSH и принесёт отчёт:

    bash remote_collect.sh                       # на текущем компьютере
    bash remote_collect.sh 192.168.0.94 --image  # + снять образ карты

Результат: otchet-192.168.0.94-<дата>.txt рядом со скриптом. Его и присылать.
Подробности и ключи: SSH_РАБОТА.txt

Вариант Б — вы уже в сеансе SSH на ноутбуке:

    sudo -i
    cd /media/*/*/pcmcia-flash-kit
    bash ./report.sh                      # файл report-<дата>.txt + экран

В нём сразу: окружение и md5 набора, мост/слот/dmesg, --probe и --cis.
Дальше шаги 4-6 нужны, только если хотите смотреть вручную.
Подробнее: SSH_РАБОТА.txt


ШАГ 4. ПОСМОТРЕТЬ, ЧТО ВИДИТ ЯДРО (1 минута, нужен root)
--------------------------------------------------------
    sudo bash ./pcmcia_flash.sh --diag

Это тот же разбор, что вы уже присылали, но в новой сборке он дополнительно
печатает состояние сокета из sysfs, опции ядра и вердикт.
Ничего не меняет, только читает. Ожидаемый вердикт в вашем случае:
"не нашло ни одного годного окна памяти ... Это ПЕРВАЯ причина".


ШАГ 5. ПРОВЕРИТЬ, ЕСТЬ ЛИ ДОСТУП К ОКНАМ ПАМЯТИ (10 секунд)
----------------------------------------------------------
    sudo python3 pcmcia_direct.py --probe

Что должно быть:
  "Доступ к /dev/mem: есть"  + hex-байты окон
      -> переходите к ШАГУ 7.

  "mmap(0x64000000, 256) не удался: Operation not permitted"
      -> это CONFIG_STRICT_DEVMEM, нужен ШАГ 5. Карта и набор тут ни при чём.

  "нужен root" -> забыли sudo.


ШАГ 6. РАЗРЕШИТЬ ДОСТУП К /dev/mem (один раз, с перезагрузкой)
-------------------------------------------------------------
ТОЛЬКО ЕСЛИ ШАГ 4 отказал. Это правка параметров загрузчика, карту не трогает.

    sudo cp /etc/default/grub /root/grub.bak
    sudo sed -i 's/^GRUB_CMDLINE_LINUX="\(.*\)"/GRUB_CMDLINE_LINUX="\1 iomem=relaxed"/' /etc/default/grub
    grep GRUB_CMDLINE_LINUX /etc/default/grub
    sudo update-grub
    sudo reboot

После загрузки (карту не вынимать):

    grep iomem /proc/cmdline          # должно быть iomem=relaxed
    sudo python3 pcmcia_direct.py --probe

Вернуть как было, если понадобится: sudo cp /root/grub.bak /etc/default/grub
и sudo update-grub.


ШАГ 7. ГЛАВНАЯ ПРОВЕРКА: ЧИТАЕТСЯ ЛИ ПАСПОРТ КАРТЫ (10 секунд)
---------------------------------------------------------------
    sudo python3 pcmcia_direct.py --cis

Почему именно так. Common memory карты (первые 4 КиБ по окну) у стёртой
карты и у неотвечающей шины выглядит ОДИНАКОВО — сплошные 0xFF. Поэтому
по обычному --probe ничего решить нельзя, там 0xFF ничего не доказывает.
Различает только attribute memory: это отдельная маленькая память ПЗУ
карты, где лежит CIS (паспорт: производитель, модель, размер, тип).
Если карта жива, CIS читается даже у полностью стёртой карты.

Что смотреть в выводе:
  "attribute memory:"  + строки кортежей (CISTPL_DEVICE, CISTPL_MANFID,
  CISTPL_VERS_1 ...)  -> карта ЖИВА и отвечает.
      Дальше: строка "производитель карты" и "размер из DEVICE" — паспорт.
      У нас ожидается intel, SERIES2-20, 16 МиБ (по прошлым логам).
      Тогда переходите к ШАГУ 7: дело не в карте, а в окнах ядра.

  кортежей 0, сплошные 0xFF или 0x00 -> карта (или контакт слота) не
      отвечает. Тогда: вынуть/вставить до щелчка, протереть контакты,
      повторить. Не помогло — попробовать в слоте ДРУГУЮ 16-битную карту.

Запасной вариант, если --cis не смог найти мост:
    sudo python3 pcmcia_direct.py            (старый режим, окна как есть)
Он печатает окна и первые 4 КиБ каждого. Но помните: 0xFF там — это
"неизвестно", а не "стёрто".


ШАГ 8. СНЯТЬ ОБРАЗ КАРТЫ (главное действие, 1-2 минуты)
------------------------------------------------------
    sudo python3 pcmcia_direct.py --read /root/card.bin --double --size auto

  --double       два чтения и сверка; при расхождении образ НЕ сохраняется
  --size auto    размер карты определится сам (по повторению адресных линий)
  если auto ошибётся — укажите вручную: --size 16m или --size 32m

В конце печатается: сколько байт, md5, и "Начало карты: <вердикт>".
Скопируйте /root/card.bin на флешку и на диск ноутбука — это ваша страховка.


ШАГ 9. ПОСМОТРЕТЬ ОБРАЗ БЕЗ КАРТЫ (по желанию)
---------------------------------------------
    python3 pcmcia_gui.py --map-file /root/card.bin

Показывает блоки: стёрто / занято / ошибки. Полезно понять, где на карте
данные, а где пустота. Карта при этом не нужна и не затрагивается.


ШАГ 10. ЕСЛИ ХОТИТЕ ПРОВЕРИТЬ САМ НАБОР (не обязательно, 2 минуты)
------------------------------------------------------------------
    sudo apt install -y xvfb            # если его ещё нет
    xvfb-run -a python3 tests/test_v2.py
    xvfb-run -a python3 tests/test_gui.py
    xvfb-run -a python3 tests/test_ui_pro.py
    python3 tests/test_scripts.py
    python3 tests/ab_regression.py pcmcia_gui.py

Ожидаемо: 95, 59, 72, 170 и "дефектов 0 из 7", везде "провалено 0".


ЧЕГО ПОКА НЕ ЗАПУСКАТЬ
----------------------
Пункты меню 5 (стереть), 6 (записать), 7 (FTL+FAT), 8 (тест записи) —
до тех пор, пока карта не читается. Запись на невидимую карту бессмысленна,
а на неисправную — вредна.

Также не помогает (проверено по их логу и коду ядра):
  * modprobe pcmciamtd mem_base=... mem_size=... force_write=...
      — таких параметров у модуля нет, ядро их выбрасывает;
  * force_size=16 при "no high memory space" — драйвер до этого не доходит;
  * смена Vpp — на чтение не влияет вообще;
  * "IO port probe ... probe failed" — это не ответ карты: ядро там ищет
    стабильный фон по всем 256 портам, у 16-битной карты порты вообще не
    нужны, pcmciamtd работает через память. Смотрите строки memory probe.


КОРОТКАЯ ВЕРСИЯ (то же самое, без объяснений)
---------------------------------------------
    cd /media/<флешка>/pcmcia-flash-kit
    bash ./remote_collect.sh              # на ТЕКУЩЕМ компьютере: сходит по SSH
    sudo bash ./report.sh                 # либо уже на ноутбуке
    sudo bash ./pcmcia_flash.sh --diag
    sudo python3 pcmcia_direct.py --probe
    #   если "Operation not permitted" -> ШАГ 6 и перезагрузка
    sudo python3 pcmcia_direct.py --cis          # есть кортежи = карта жива
    sudo python3 pcmcia_direct.py --read /root/card.bin --double --size auto
    python3 pcmcia_gui.py --map-file /root/card.bin
